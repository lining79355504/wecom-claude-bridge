# wecom-claude-bridge 功能与使用手册

适用版本：当前项目 `0.1.0`，包含工单管理、定时 Claude 任务和企业微信群 Webhook 推送。

本项目将企业微信智能机器人与本机 Claude Code 连接起来。你可以在企微提交开发需求、补充说明、审批工具操作，也可以创建定时任务，让 Claude 定期处理工作并发送结果。

本文中的安装命令在运行桥接服务的电脑终端执行；以 `/new`、`/schedule` 等开头的命令在企微中发给桥接机器人。示例路径、密钥、编号需要替换为实际值。

## 1. 功能概览

| 功能 | 使用方式与行为 |
|---|---|
| 企微远程操作 Claude | 发送文字需求，Claude 在配置的本机工作目录内处理 |
| 文本与语音输入 | 支持文本；语音使用企业微信提供的转写结果 |
| 工单管理 | 创建、切换、查看历史、停止、恢复、验收关闭 |
| 工单上下文 | 每张工单独立保存 Claude 会话；补充消息归入当前工单 |
| 执行反馈 | 交互工单显示流式进度和最终结果，流式结果发送失败时尝试主动推送 |
| 工具审批 | 按权限模式自动处理或发送人工审批请求 |
| 访问控制 | 用户白名单、允许访问的目录、禁用工具配置 |
| 定时执行 | 支持固定间隔、每天指定时刻、指定日期的一次性任务 |
| 定时任务并发 | 独立执行池，默认并发 4 个任务；同一任务不重叠执行 |
| 结果推送 | 定时结果发回创建任务的聊天，或发到群机器人 Webhook |
| 发送重试 | 独立推送队列、消息分段、目标限速、自动与手动重试 |
| SQLite 持久化 | 保存工单、消息、定时任务、运行记录和待发送结果 |

运行链路：

```text
企微消息 → 白名单验证 → 工单命令 / 定时任务命令
                            │
               ┌────────────┴─────────────┐
               ↓                          ↓
          工单串行队列              定时任务并发池
               ↓                          ↓
          Claude 会话               每次新建 Claude 会话
               ↓                          ↓
         企微进度与结果              SQLite 保存结果
                                          ↓
                                    独立推送队列
                                          ↓
                              原聊天 / 群机器人 Webhook
```

桥接通过 WebSocket 长连接接收企微消息，无需自行部署公网回调入口。运行机器仍需要能够访问企业微信和 Claude 所需的网络服务。

## 2. 安装与首次启动

### 2.1 准备条件

| 项目 | 要求 |
|---|---|
| Node.js | 至少 `22.13.0`，推荐 Node.js 24 |
| Claude Code | 已安装 `claude` 命令，并在运行桥接的系统账号下完成可用的认证配置 |
| 企业微信智能机器人 | 已取得用于长连接的 Bot ID 和 Secret |
| 工作目录 | 已存在的项目目录；建议填写绝对路径 |
| 白名单 | 允许使用桥接的用户标识，至少一个 |
| SQLite | 使用 Node.js 内置模块，不需要安装数据库服务 |
| 群机器人 Webhook | 可选，仅在向指定群推送定时结果时需要 |

企微智能机器人的 Secret、自建应用的 Secret、群机器人的 Webhook 是不同配置，不能互相代替。

### 2.2 安装项目依赖

进入本项目目录执行：

```bash
cd /path/to/wecom-claude-bridge
npm install
```

首次配置时复制模板；如果 `.env` 已存在，保留原文件并按需补充配置：

```bash
test -f .env || cp .env.example .env
```

### 2.3 配置必要参数

编辑项目根目录下的 `.env`：

```dotenv
WECOM_BOT_ID=替换为智能机器人BotID
WECOM_BOT_SECRET=替换为智能机器人Secret
WECOM_ALLOWED_USER_IDS=替换为获准用户标识
CLAUDE_WORKSPACE=/absolute/path/to/your-project
CLAUDE_PERMISSION_MODE=default
```

Bot ID 和 Secret 从企业微信管理后台对应智能机器人的开发设置中获取。多个白名单成员用英文逗号分隔。

`CLAUDE_WORKSPACE` 是 Claude 实际操作的项目目录，不一定是桥接程序自身的目录。不要使用 `~`；目录含空格时可在 `.env` 中为值加引号。

如果暂时不知道自己的用户标识，可以按以下方式从桥接日志确认：

1. 先配好机器人凭证和工作目录。
2. 将 `WECOM_ALLOWED_USER_IDS` 临时设置为不对应真实成员的占位值，例如 `bootstrap-deny-all`。这样能够启动，但真实用户仍无法通过白名单验证。
3. 运行 `npm start`，在企微给该机器人发送一条文字消息。
4. 在本机终端查找“拒绝非白名单用户”日志，将其中的实际标识填回白名单，删除占位值。
5. 停止并重新启动桥接。

白名单留空时，程序会在连接前拒绝启动，因此无法通过“留空后发消息”的方式获取标识。

### 2.4 自检与启动

```bash
npm run check
npm start
```

看到“认证成功”后，在企微发送：

```text
/help
```

随后创建一个只读需求验证整个链路：

```text
/new 查看当前项目结构，说明主要模块，不修改文件
```

`npm run check` 检查配置、目录、模块加载和 `claude --version`。它不会连接企微，也不会实际调用模型；自检通过不代表机器人凭证、模型认证或网络链路已经验证成功。

### 2.5 停止与重新启动

前台运行时按 `Ctrl+C` 停止。程序会请求中止活动任务并关闭连接，退出等待上限约 10 秒。修改 `.env` 后，需要重新启动桥接才能按新配置工作。

同一机器人和数据库只运行一个桥接进程。不要在旧进程仍运行时再启动第二个副本；新的长连接可能挤掉原连接。

## 3. 工单操作

### 3.1 创建与补充需求

在企微发送：

```text
/new 分析登录接口响应慢的原因，先给出排查结论
```

机器人返回工单编号并开始处理。后续直接发送普通文字，会补充到当前选中的工单：

```text
重点检查数据库查询，暂时不要修改前端
```

如果没有当前工单，普通文字会自动创建工单；当前工单已关闭时，下一条普通需求也会创建新工单。

### 3.2 命令参考

| 命令 | 功能 |
|---|---|
| `/new 需求描述` | 创建并选中新工单，提交执行 |
| `/list` | 查看当前聊天最近 20 张工单，标记当前选中项 |
| `/switch 编号` | 切换后续消息归属，不中断已在执行的工单 |
| `/status [编号]` | 查看状态、目录、排队数量、会话及审批信息 |
| `/history [编号]` | 查看最近 10 条记录，每条展示最多 500 字符 |
| `/stop [编号]` | 中止执行，取消该工单尚未执行的排队消息 |
| `/resume [编号]` | 恢复暂停消息，或让 Claude 核查进度后继续处理 |
| `/close [编号]` | 验收并关闭，保留历史 |
| `/reset [编号]` | 清空 Claude 会话，保留工单和历史 |
| `/clear [编号]` | 与 `/reset` 相同 |
| `/verbose [on|off]` | 查询或切换本聊天的详细执行进度，默认关闭 |
| `/help` 或 `/?` | 查看帮助 |

方括号表示可选参数，发送命令时不要输入方括号。通常省略编号表示当前工单；`/stop` 省略编号时，会优先停止本聊天正在执行的工单。

工单编号、定时任务编号、定时运行编号分别使用，不能混用。例如 `/stop 1` 操作工单，`/schedule stop 1` 操作定时任务。

### 3.3 一次完整处理流程

按顺序发送以下消息，并在需要时等待上一步完成：

```text
/new 修复接口的空参数校验问题
```

机器人返回工单编号后，可以查询或补充：

```text
/status
请补充相应测试，并说明验证结果
```

处理完成后查看记录并验收：

```text
/history
/close
```

Claude 完成回复后，工单进入“待验收”；只有执行 `/close` 才会关闭。仍有运行或排队任务时，需要先停止并等待退出，才能关闭或重置。

### 3.4 状态与队列

| 状态 | 含义 |
|---|---|
| 待处理 | 工单已创建，尚未开始处理 |
| 排队中 | 等待执行 |
| 执行中 | Claude 正在处理 |
| 待审批 | 等待工具操作审批 |
| 待验收 | Claude 已成功完成本轮，等待用户确认 |
| 已中止 | 用户停止，或重启后暂停 |
| 执行失败 | 本轮未成功完成 |
| 已关闭 | 用户验收关闭 |

所有聊天的交互工单共用一个串行执行队列。执行期间补充的消息会排队，不会插入正在进行的一轮；要立即改变方向，可先 `/stop`，等退出后重新提交需求。

`/stop` 取消的排队消息不会被后续 `/resume` 自动重新提交；历史仍保留，需要执行的内容应重新发送。一次失败会暂停同工单后续消息，其他工单可继续排队执行。

不同聊天的工单相互隔离。同一群聊中的白名单成员共享工单和当前选中项。工单隔离的是对话上下文，文件仍位于配置的实际工作目录中。

### 3.5 图片、截图与图片回传

直接发送图片或图文消息即可进入当前工单；没有当前工单时自动创建。图文中的 `/new 需求` 可以带图片创建新工单。每条最多 4 张，单张最多 5 MiB，输入格式为 PNG、JPEG、GIF、WebP。图片下载先检查白名单；同一聊天按接收顺序提交，避免图片下载期间后续文字、切换命令先执行。

常见用法：

- 发截图并说明“解释这个报错，检查相关代码”。
- 发图片并说明“裁剪右上角，另存为 PNG 后发给我”。
- 发送“把 screenshots/result.png 发给我”。
- 发送“截取当前屏幕，保存到工作目录并发给我”。

图片内容会直接传给 Claude，并在工单工作目录的 `.wecom-bridge-media/` 中生成本地副本。识图需要当前模型支持视觉；截图和图片编辑使用本机已有工具，可能需要工具审批或系统授权，例如 macOS 屏幕录制权限。本功能没有额外安装截图、图像编辑或图像生成软件。

Claude 使用 `mcp__wecom_images__send_image` 将本地图片上传并发送到当前工单所在单聊或群聊；不能自行指定其他收件人。发送仅支持 PNG/JPEG，最大 2 MiB，大图或其他格式需先转换。发送动作遵守现有权限模式，路径受 `CLAUDE_ALLOWED_PATHS` 限制，并检查真实路径与符号链接；可通过 `DENIED_TOOLS` 禁用该工具。上传或发送失败会明确返回错误；停止工单后，尚未进入发送步骤的图片不会继续发送。

原图保存在工单 SQLite 数据库中，重启后无需重新使用已经过期的下载链接；`/resume` 会恢复图片任务。历史图片、本地副本和编辑结果不会自动清理，关闭工单也不删除图片。请将 `.wecom-bridge-media/` 加入实际工作目录的 Git 忽略规则（本仓库已配置）。备份数据库包含收到的原图；备份本地副本和编辑结果仍需保留工作目录。清理副本后，恢复队列时会从数据库重新生成输入图片。

定时任务仍只推送 Markdown。接收普通文件附件、引用消息中的图片尚未支持。

### 3.6 文件发送

可以在交互工单中要求 Claude 把本地文件发回当前单聊或群聊：

```text
把 reports/分析报告.pdf 发给我
把测试结果保存为 result.txt，然后作为文件发给我
把生成的代码打包成 zip，发到当前聊天
```

Claude 使用 `mcp__wecom_files__send_file` 读取、上传并发送真实文件，保留原始文件名（包括中文、空格和扩展名）。支持 PDF、文本、代码、压缩包等非空普通文件；单个文件上限为 20 MiB，目录需先打包，超限文件需先压缩或拆分。相对路径从工单工作目录解析。

发送工具沿用当前权限模式，受目录围栏和工具禁用配置约束，并检查符号链接的真实目标。可在 `DENIED_TOOLS` 中添加 `mcp__wecom_files__send_file` 禁止文件发送。收件人由桥接程序绑定为当前工单所在聊天，Claude 不能用该工具指定其他收件人。

仅上传和发送均成功时才报告“已发送文件”。失败会告知原因，不自动重复发送；停止工单后，尚未进入发送步骤的文件不会继续发送。已进入发送步骤的消息不能通过停止工单撤回。文件发送没有独立的持久化重试队列，发出的文件内容不另存入工单数据库。

更新代码后重启桥接进程即可使用，无新增依赖或必填配置。接收普通文件附件和定时任务附件推送尚未支持。

### 3.7 详细执行进度

```text
/verbose on
/verbose
/verbose off
```

`/verbose on` 开启详细进度，`/verbose off` 关闭，省略参数查询状态；允许多个空格，例如 `/verbose  on`。无需先创建工单，命令不会创建任务或改变审批模式。设置按聊天保存在 SQLite，同群成员共享，其他聊天不受影响，重启后保留。`/status` 也会显示当前开关。

开启后，每轮使用同一条“流式消息＋模板卡片”组合回复：正文显示执行状态与最终答案，过程默认折叠在该回复中，不另发过程卡片。点击“展开过程”查看，使用“上一页”“下一页”翻阅，“刷新”更新当前页，“最新”跳到末页，“收起”隐藏内容。群聊只更新点击者视图，卡片点击不创建工单或调用 Claude。

过程包含 SDK 提供的面向用户的执行说明、工具调用的命令或路径、工具文本结果和错误。不镜像 terminal 的 ANSI 界面、交互控件或 SDK 未提供的输出，不透传内部思维链和二进制工具结果。内容在 SDK 返回完整块后可见，不逐字输出。

运行中可切换，对后续事件立即生效，不回放此前未记录的内容。每轮从头保留最多 256 KiB 过程文本，每页最多 900 字节；达到上限时明确标记并停止追加，不丢弃早期记录。卡片通过点击刷新，最终答案更新同一条回复正文。正文超过 3800 字节时提示截断，完整答案保留在工单数据库中。过程记录随数据库保存，任务结束和重启后仍可展开，需桥接在线且企微仍允许卡片交互。`/history` 展示需求和最终结果，过程通过卡片查看。

开启时，立即执行的请求不再额外发送保存回执。排队通知、审批、命令回执和媒体附件仍独立发送；流式通道失败时，最终结果回退主动推送，无法保证仍在原消息中。关闭时保留约每 2 秒刷新的简短工具进度。定时任务仍按原规则推送结果。

## 4. 权限与审批

### 4.1 权限模式

通过 `.env` 的 `CLAUDE_PERMISSION_MODE` 设置：

| 值 | 行为 |
|---|---|
| `default` | 采用默认权限判断；本地只读策略可放行，其他需要人工判断的操作发起审批 |
| `acceptEdits` | Claude 自动接受文件编辑，其余操作继续按权限规则处理 |
| `auto` | Claude 原生分类器自动判断；无法决定时回退到人工审批，是否可用取决于模型、账号和组织策略 |

三种模式都会先执行目录围栏和禁用工具检查。`auto` 模式回退到人工审批时，不再使用本地只读名单自动放行该请求。

### 4.2 工单审批

收到工具审批提示后，在同一聊天中回复提示里的完整编号，例如：

```text
y 1-a1b2c3d4
```

拒绝则发送：

```text
n 1-a1b2c3d4
```

这里的编号只是格式示例，必须使用当前提示中的真实审批编号。裸 `y`、错误编号、过期编号以及其他聊天的回复不能批准操作。默认 5 分钟没有答复自动拒绝。

### 4.3 定时任务审批

定时任务使用独立命令：

```text
/schedule approve s12-a1b2c3d4
/schedule reject s12-a1b2c3d4
```

根据意图只发送其中一条，并替换为实际审批编号。审批提示发到创建定时任务的桥接聊天，即使结果配置为发往另一个群 Webhook，也在原聊天中审批。

每次定时运行有独立审批，不会覆盖其他定时运行的审批。同一运行同时出现多个需要审批的工具请求时，已有请求保留，后续请求被拒绝。长连接离线时，需要人工审批的定时工具操作会被拒绝。

### 4.4 目录和工具策略

```dotenv
# 限制为两个项目目录；填写后以这里的列表为准
CLAUDE_ALLOWED_PATHS=/absolute/path/project-a,/absolute/path/project-b

# 所有模式都禁用这些工具
DENIED_TOOLS=WebFetch

# 关闭 Bash 命令的本地只读自动放行
BASH_READONLY_AUTO_APPROVE=false
```

`CLAUDE_ALLOWED_PATHS` 留空时，允许目录默认为 `CLAUDE_WORKSPACE`；填入列表时，不会自动把工作目录追加到列表。设为 `*` 会取消目录范围限制。

`READ_ONLY_TOOLS` 可调整本地自动放行的工具名单。Bash 还会检查命令内容和参数：简单的 `git status`、`ls` 等可被判定为只读；重定向、变量展开、命令替换或不认识的命令会回退到权限判断。组合命令会分段检查，不应仅凭使用了 `&&` 就判断一定需要审批。

目录围栏和命令分析是应用层检查，不是操作系统沙箱；命令分析、符号链接等情况存在边界。应仅给可信成员使用，并将允许目录限定为工作所需范围。

<a id="schedules"></a>

## 5. 定时任务

### 5.1 创建语法

```text
/schedule add 时间类型 时间值 [可选参数] -- 任务内容
```

`--` 是必须的分隔符，之后全部视为 Claude 任务内容，可以包含多行文字。配置参数应放在分隔符之前。

| 时间类型 | 示例 | 行为 |
|---|---|---|
| `every` | `every 30m`、`every 2h`、`every 1d` | 固定间隔，单位为分钟、小时、天；范围 1 分钟至 366 天 |
| `daily` | `daily 09:00` | 在指定时区每天执行 |
| `once` | `once 2027-01-01T09:00+08:00` | 在未来时间执行一次，必须带时区偏移或 `Z` |

首次创建 `every 30m` 时，第一次自动执行约在 30 分钟后。想先验证效果，可使用 `/schedule run 编号`。

目前不支持直接输入 Cron 表达式或用自然语言创建调度规则。把“每天九点”写在任务内容中，不会自动成为每天九点的调度设置。

### 5.2 可选参数

| 参数 | 用途 |
|---|---|
| `--timezone Asia/Shanghai` | 指定 `daily` 使用的 IANA 时区 |
| `--workspace "/absolute/path/project"` | 指定本任务的工作目录；必须存在且位于当前允许范围 |
| `--webhook https://qyapi.weixin.qq.com/cgi-bin/webhook/send?key=...` | 将最终结果推送到指定群机器人 |

省略工作目录时，任务绑定创建时的 `CLAUDE_WORKSPACE`。省略 Webhook 时，发回创建任务的单聊或群聊。参数不能重复，含空格的目录需要引号包裹。

### 5.3 创建示例

每半小时检查仓库：

```text
/schedule add every 30m -- 检查当前仓库状态，总结新增提交和未提交修改，不修改文件
```

每天北京时间九点总结昨天的工作：

```text
/schedule add daily 09:00 --timezone Asia/Shanghai -- 总结昨天的代码提交，按功能、修复、风险组织结果
```

指定一次性检查时间：

```text
/schedule add once 2027-01-01T09:00+08:00 -- 检查项目发布准备情况并输出待办清单
```

一次性任务的示例日期仅作格式演示，创建时必须改成未来时间。

### 5.4 管理命令

| 命令 | 功能及注意事项 |
|---|---|
| `/schedule` 或 `/schedule help` | 查看帮助 |
| `/schedule list` | 查看当前聊天的任务 |
| `/schedule show 任务编号` | 查看内容、规则、目录、目标类型、下次执行时间及审批 |
| `/schedule history 任务编号` | 最近 10 次运行，包含执行和推送状态、结果预览 |
| `/schedule pause 任务编号` | 暂停后续调度并取消尚未执行的排队项；当前执行继续 |
| `/schedule resume 任务编号` | 恢复后续调度，重新计算下一次执行时间 |
| `/schedule run 任务编号` | 立即排队运行一次，不改变原周期；暂停任务也可以手动运行 |
| `/schedule stop 任务编号` | 中止当前运行并取消排队；保留之后的自动调度 |
| `/schedule delete 任务编号` | 停止调度、中止执行、取消未发送结果；数据库历史保留 |
| `/schedule retry 运行编号` | 对自动重试耗尽的推送重新排队，不重新执行 Claude |
| `/schedule approve 审批编号` | 同意当前审批 |
| `/schedule reject 审批编号` | 拒绝当前审批 |

同一任务已有排队或执行中的运行时，`run` 会被拒绝，避免重复执行。要停止当前执行并暂停后续触发，可依次执行：

```text
/schedule pause 1
/schedule stop 1
```

当前没有修改已创建任务的命令。调整内容、时间、工作目录或 Webhook 时，先暂停或删除旧任务，再重新创建。

### 5.5 时间和上下文

默认 `daily` 时区为 `Asia/Shanghai`，可通过 `SCHEDULE_TIMEZONE` 或单个任务的 `--timezone` 改变。已有任务保存创建时的规则，不会随着默认时区修改而变化。

详情中的下次执行时间使用 UTC 的 ISO 格式，例如 `2026-11-19T01:00:00.000Z` 对应北京时间当天 09:00。使用有夏令时的时区时，当天不存在的时刻跳过，回拨产生的重复小时只执行一次。

每次定时运行都创建新的 Claude 会话，不自动沿用上一次运行的对话。需要跨次比较时，应在任务中明确要求读取持久化的报告或状态文件，并按实际权限完成写入。

### 5.6 看懂执行与推送状态

| 执行状态 | 含义 |
|---|---|
| `queued` | 已进入执行队列 |
| `running` | Claude 正在执行，可能正在等待审批 |
| `succeeded` | Claude 成功完成本轮 |
| `failed` | 执行失败、超时或权限检查失败 |
| `cancelled` | 运行或排队已取消 |
| `interrupted` | 进程退出或重启导致执行中断 |

| 推送状态 | 含义 |
|---|---|
| `pending` | 等待发送、网络恢复、限速间隔或下一次重试 |
| `sent` | 所有消息分段已确认发送成功 |
| `failed` | 自动尝试次数已耗尽，可手动 `retry` |
| `cancelled` | 删除任务后取消尚未完成的推送 |
| 尚无结果 | 当前没有对应的待发送结果 |

`succeeded` 与推送 `failed` 可以同时出现，表示任务已完成但消息没有成功送达。应使用 `retry 运行编号`，而不是用 `run` 重复执行任务。

<a id="webhook"></a>

## 6. 企业微信群 Webhook 推送

### 6.1 准备目标

在需要接收结果的企业微信群中配置群机器人，取得该群机器人的 Webhook 地址。具体创建入口和可用性取决于企业微信客户端及组织设置。

当前支持的地址格式：

```text
https://qyapi.weixin.qq.com/cgi-bin/webhook/send?key=你的群机器人密钥
```

仅支持官方 HTTPS 地址，不支持 HTTP、自建中转域名、其他服务的 Webhook 或重定向地址。

### 6.2 配置并验证

在桥接机器人所在的聊天中发送：

```text
/schedule add daily 18:00 --timezone Asia/Shanghai --webhook https://qyapi.weixin.qq.com/cgi-bin/webhook/send?key=你的群机器人密钥 -- 生成项目日报，包含今日提交、未完成事项和风险
```

创建成功后，使用返回的任务编号手动执行，例如：

```text
/schedule run 1
/schedule history 1
```

等待执行完成，并在目标群确认结果。`history` 可用于判断是 Claude 执行失败还是发送失败。

### 6.3 使用约定

- 群 Webhook 仅作为定时任务结果的发送目标，不能通过它接收命令或审批回复。
- 任务管理和人工审批仍在创建任务的桥接聊天中完成。
- 创建命令中的 `--webhook` 参数不会加入 Claude 提示词；不要把密钥再次写进 `--` 后的任务正文。
- 查询展示隐藏 Webhook 地址，数据库中仍需保存地址，以便重启后发送。创建命令本身也会保留在企微聊天记录中，应选择适合的管理聊天。
- Webhook 密钥失效或轮换时，暂停旧任务并使用新地址重新创建。
- 默认发送 Markdown，长结果会按字节分段；当前没有定时附件推送能力。

<a id="concurrency"></a>

## 7. 并发、超时与重试

### 7.1 多任务同时触发

项目使用三条独立处理通道：

| 通道 | 默认处理方式 |
|---|---|
| 交互工单 | 全部聊天共用一个串行队列 |
| 定时 Claude 执行 | 最多同时执行 4 个任务 |
| 定时结果推送 | 最多同时发送 4 路消息，与 Claude 执行池分开 |

假设五个定时任务同时到期，前四个进入执行，第五个排队。其中一个任务等待审批时，其他三个仍可执行；任意运行结束后，排队任务就能获得空闲槽位。

并发有上限，因此所有槽位都被占用时，新任务仍需等待。慢 Webhook 不占 Claude 执行槽位；如果全部发送槽位被占用，其他推送也需要等待发送槽位释放。

同一任务最多有一项排队或执行中的运行。上次还没完成时再次到期，不会再积累一条运行。停机错过多个周期时最多补一轮，然后继续计算后续时刻。

### 7.2 调整并发和超时

```dotenv
SCHEDULE_CONCURRENCY=4
SCHEDULE_MAX_TURNS=100
SCHEDULE_DELIVERY_CONCURRENCY=4
SCHEDULE_TIMEOUT_MS=1800000
```

两个并发配置支持 `1` 至 `32` 的整数。并发越高，对 CPU、内存、模型额度和上游服务的要求越高，应根据机器和账号条件调整。

单次定时执行默认最多 30 分钟，包含审批等待时间。超时后请求 SDK 中止，只有实际退出才释放槽位，防止同一任务重叠。停止不会回滚已经发生的文件修改或外部操作。

定时任务还有独立的 agent 轮数限制，默认 `SCHEDULE_MAX_TURNS=100`，支持 1–1000 的整数。轮数指 Claude 在一次任务内推进工作所用的交互轮次，不是定时任务触发次数，也不等于精确的工具调用次数。普通工单仍使用 `CLAUDE_MAX_TURNS`，默认 30 轮。

出现 `Reached maximum number of turns` 时，本轮已经达到轮数上限。程序将运行标记为失败，并保存已收到的部分输出，部分输出不代表最终结果。可以缩小任务范围，或在 `.env` 提高 `SCHEDULE_MAX_TURNS` 后重启桥接，再核查已完成的操作并使用 `/schedule run 任务编号` 从新会话重跑；当前没有从失败定时会话继续执行的命令。提高轮数可能增加时间和模型用量，30 分钟超时仍独立生效。`/schedule retry 运行编号` 不会恢复执行。

各个会话独立，但不会自动为任务创建文件系统隔离。并发修改不同项目时使用 `--workspace`；并发修改同一仓库时，应预先准备独立 worktree 或目录，避免多个任务修改同一份文件。

### 7.3 推送规则

| 项目 | 当前行为 |
|---|---|
| 单目标发送间隔 | 至少 3.1 秒，包含重试；不同目标可并发 |
| 分段大小 | 每段不超过 3800 UTF-8 字节，中文和表情按实际字节计数 |
| Webhook 请求超时 | 10 秒 |
| 自动尝试次数 | 每段最多 5 次，包含首次发送 |
| 重试等待 | 指数退避，失败后等待时间逐次增加，最多 60 秒 |
| 结果保留 | 推送失败时保留已经生成的结果 |
| 手动重试 | `/schedule retry 运行编号`，仅用于自动重试耗尽的推送 |

已经确认送达的分段不会在后续正常重试中重复发送。网络确认丢失，或远端已接收而本地尚未保存成功状态时进程退出，仍可能导致消息重复；当前不能保证外部消息恰好发送一次。

同一群机器人的其他发送程序也会消耗平台频率额度。平台限流或错误会记录在推送状态中。

|---|---|---|

```text
Read,Glob,Grep,LS,NotebookRead,WebFetch,WebSearch,TodoWrite,Task
```

名单名称不表示其中每个工具都只读，应按自身需求配置。要关闭桥接层的工具名单与 Bash 自动放行，可同时设置：

```dotenv
READ_ONLY_TOOLS=
```

## 9. 持久化、重启与备份

### 9.1 保存内容

SQLite 保存工单及选择状态、聊天消息、详细进度开关、每轮过程卡片的有界文本记录、工单队列、Claude 会话标识、定时任务配置、每次定时运行的状态与结果、待发送分段及发送进度。

数据库目录会按需创建，`data/`、`.env` 和 SQLite 文件已配置为 Git 忽略。日志默认输出到运行终端，不会自动保存成日志文件。

### 9.2 重启后会发生什么

| 重启前的情况 | 重启后的行为 |
|---|---|
| 工单正在执行或排队 | 暂停，用户用 `/resume 编号` 继续 |
| 工单待审批 | 旧审批失效，恢复后按新的请求判断 |
| 定时任务已排队但没开始 | 自动继续执行 |
| 定时任务已经开始但被中断 | 标记 `interrupted`，不自动重跑这次操作；后续正常周期继续 |
| 定时结果已生成但未发完 | 继续处理保存的发送队列 |
| 离线期间错过多个定时周期 | 合并遗漏触发，最多补一轮 |

恢复工单上下文还依赖本机 Claude 会话文件，仅复制 SQLite 不能保证原会话能够恢复。定时任务每次使用新会话，不依赖上一轮对话继续执行。

### 9.3 备份与恢复

建议在计划维护时使用以下流程：

1. 确认正在执行的任务，按需要先停止或等待完成。
2. 正常停止桥接，确保进程已经退出。
3. 备份 `TICKET_DB_PATH` 对应数据库及仍存在的 `-wal`、`-shm` 配套文件。默认路径可直接备份整个 `data/` 目录。
4. 单独保存 `.env`、实际项目文件以及需要恢复的本机 Claude 会话数据。
5. 恢复时保持桥接停止，使用同一批次备份文件和正确的配置，再运行自检和启动。

运行中直接复制单个 SQLite 主文件可能遗漏 WAL 中的数据；需要在线备份时，应使用 SQLite 的一致性备份能力。

数据库包含任务内容、结果和群 Webhook 地址；`.env` 包含机器人凭证。备份应限制访问，不提交到代码仓库或发到普通群聊。

## 10. 常用场景

### 10.1 在两个工单之间切换

先创建两项需求：

```text
/new 排查登录接口超时
/new 为订单接口补充测试
/list
```

从列表取得第一个工单的实际编号，再切换并补充：

```text
/switch 1
优先排查数据库连接池，暂时不要修改超时时间
```

切换只改变后续消息归属，已在运行的任务仍继续执行。

### 10.2 每天向原聊天推送日报

```text
/schedule add daily 18:00 --timezone Asia/Shanghai -- 阅读今天的 Git 提交与当前工作区状态，输出完成事项、未完成事项和风险，不修改文件
```

适合个人日报或在桥接机器人所在群接收汇总。

### 10.3 两个项目同时巡检

先在配置中允许两个项目目录，并重启：

```dotenv
CLAUDE_ALLOWED_PATHS=/absolute/path/project-a,/absolute/path/project-b
SCHEDULE_CONCURRENCY=4
```

再分别创建任务：

```text
/schedule add daily 09:00 --workspace /absolute/path/project-a -- 检查项目 A 的代码状态并总结
/schedule add daily 09:00 --workspace /absolute/path/project-b -- 检查项目 B 的代码状态并总结
```

两个任务可在相同时间进入不同的执行槽位。

### 10.4 已完成但没有收到结果

先查看任务的历史：

```text
/schedule history 1
```

如果某次运行显示执行 `succeeded`、推送 `failed`，记录其运行编号，例如 `12`，再发送：

```text
/schedule retry 12
```

如果推送仍为 `pending`，应先排查连接、限速和自动重试等待；`retry` 只用于自动尝试耗尽的失败推送。

## 11. 故障排查

| 现象 | 检查或处理方式 |
|---|---|
| 启动提示缺少配置 | 核对 `.env` 的必填项，从项目根目录执行启动命令 |
| 白名单为空，无法启动 | 填入获准用户；需要确认标识时参考首次启动的占位值流程 |
| 提示不在白名单 | 核对本次接收消息的用户标识与配置，修改后重启 |
| `node:sqlite` 加载失败 | 检查 Node.js 版本，推荐使用 Node.js 24 |
| 找不到 `claude` | 在运行桥接的系统账号和环境中检查安装及 `PATH` |
| 自检通过但模型执行失败 | 自检未实际调用模型；检查 Claude 认证、网络、账号额度和权限模式支持情况 |
| 企微认证失败 | 确认凭证属于当前智能机器人，而非自建应用或群 Webhook |
| 连接反复断开 | 检查网络、电脑休眠及是否有第二个进程连接同一机器人 |
| 普通消息一直排队 | 工单共用串行队列，查看正在执行的工单和审批请求 |
| 切换工单后 `/stop` 停了另一张工单 | 默认优先停止本聊天正在执行项；指定编号可明确目标 |
| 工单重启后没有自动继续 | 使用 `/status` 核查，再用 `/resume 编号` 恢复 |
| `/close` 或 `/reset` 被拒绝 | 仍有执行或排队项，先停止并等待实际退出 |
| 定时任务创建提示用法错误 | 检查时间规则、参数位置及任务内容前的 `--` 分隔符 |
| 定时任务时间看起来差几个小时 | 详情的下次时间是 UTC；核对任务时区和 `Z` 后缀 |
| 每日任务到点未执行 | 检查启停状态、进程是否运行、机器是否休眠、并发槽是否已满 |
| 定时任务一直运行 | 查看是否待审批；超时会请求中止，但要等 SDK 实际退出才释放槽位 |
| 提示 `Reached maximum number of turns (30)` | 旧版本定时任务沿用工单 30 轮上限；更新代码并重启后默认使用独立的 100 轮上限。也可缩小任务范围或设置 `SCHEDULE_MAX_TURNS`；核查已有操作后使用 `run` 重跑，`retry` 不能恢复执行 |
| 同一任务无法再次 `run` | 已有运行或排队项，等待完成，或先停止并等待退出 |
| `/schedule pause` 后仍有结果 | 暂停不终止已运行的一轮，也不取消已生成的待推送结果 |
| `/schedule stop` 后过一段时间又运行 | `stop` 只停止本轮，若需停止后续调度还要 `pause` 或 `delete` |
| 定时任务审批没有出现在结果群 | 审批发到创建任务的桥接聊天，群 Webhook 只接收结果 |
| 已生成结果但未送达 | 查看 `history` 的推送状态和错误；检查 Webhook 是否有效、网络及平台限流 |
| 推送 `retry` 提示没有可重试项 | 必须填写运行编号，且发送状态须已耗尽自动重试并进入 `failed` |
| 目录被拦截 | 核对任务绑定目录与当前 `CLAUDE_ALLOWED_PATHS`，修改后重启 |
| 创建人已不在白名单 | 定时执行前会重新验证；调整授权，或由获准成员重新创建任务 |
| 一次性任务无法恢复 | 过期单次规则不能 `resume`；核查后手动 `run`，或创建新的未来时间任务 |

排查时先区分“创建失败”“执行失败”“推送失败”。查看本机日志，并结合 `/status`、`/history`、`/schedule show`、`/schedule history` 判断，不要仅因未收到消息就重复执行可能有副作用的任务。

## 12. 使用边界与项目结构

### 12.1 当前边界

- 支持文本、语音转写、图片和图文输入，以及交互工单的 PNG/JPEG 图片回传和文件发送；接收普通文件附件及引用图片未接入。图片限制见 3.5 节，文件发送见 3.6 节。
- 定时结果以 Markdown 推送，尚无定时图片、文件或附件发送配置。
- 定时任务支持间隔、每日和单次规则，没有 Cron、工作日规则或自然语言调度解析。
- 定时任务暂不支持原地修改，修改时暂停或删除旧任务后重新创建。
- 创建、管理、审批按聊天范围隔离；同群的白名单成员共享管理能力。
- 工单与定时任务都直接操作实际工作目录，停止、失败或重启不会回滚已完成的操作。
- 并发池提供有限并发，不代表无限并发，也不会自动建立独立 worktree。
- 单个数据库使用单个桥接进程，没有提供多副本协调或分布式部署能力。
- 定时调度不是系统级唤醒服务；关机、休眠、进程退出期间无法准点执行。
